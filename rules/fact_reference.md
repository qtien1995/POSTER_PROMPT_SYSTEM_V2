# Fact Lock + Reference DNA

## Fact Lock
For insurance, health, finance, product, legal, or numerical content:
- `VERIFIED`: safe to render when supported by user-provided/approved source.
- `NEEDS_VERIFICATION`: do not render as a factual claim yet.
- `DO_NOT_USE`: inaccurate, misleading, unsupported, or prohibited simplification.

Never fabricate:
- policy benefits;
- coverage amounts;
- return rates;
- exclusions/conditions;
- medical/legal assertions;
- product performance.

Creative metaphors and audience hypotheses are not facts; keep them clearly separate from factual claims.

## Reference modes
### INSPIRATION — default
Analyze transferable DNA, then design a new solution.
Extract only what is useful:
- layout/grid;
- hierarchy;
- palette;
- typography logic;
- composition/camera;
- lighting;
- material/texture;
- metaphor mechanism;
- information architecture;
- emotional positioning;
- what must NOT be copied.

### RECREATION
Use only when the user requests close structural fidelity. Preserve approved composition/relationships/style closely while changing requested content.

## Reference learning rule
A returned or reference image is not automatically a permanent rule.
Save/promote its DNA only when the user explicitly wants it reused as a project style.
